# AI 外设调试精简规范

目标：减少无效试错，让 AI 可以独立完成编译、刷写、复位、抓日志、恢复和验收。

## 开始前准备

- 硬件资料：开发板型号、PCB 版本、主控型号和 Silicon Revision、原理图、引脚表。
- 外设资料：模块型号、芯片型号、排线方向、供电方式、官方源码、SDK 版本。
- 调试链路：稳定 USB 数据线、串口、烧录工具、编译环境、网络访问。
- 物理状态：说明已插入哪些模块、哪些总线或电源共享、是否允许自动刷写。
- 人工动作：如果 AI 无法控制电源，约定需要冷启动时由用户断电 10 秒并回复“已上电”。

不要只提供 `.bin`。尽量同时提供源码、`sdkconfig`、分区表和官方文档。

## 固定执行顺序

1. 记录芯片 Revision、MAC、Flash、PSRAM、串口号和工具链版本。
2. 首次实验前备份完整 Flash，保存 SHA-256。
3. 准备恢复固件，确认失败后可以回到已知可用状态。
4. 先运行最小总线探测：确认地址 ACK 和固定芯片 ID。
5. 再运行单外设驱动：关闭 LCD、网络、AI 推理等无关模块。
6. 验证真实数据流，不以“识别到设备”作为最终成功。
7. 每轮只改变一个变量，并保存刷写命令、固件 SHA-256 和串口日志。
8. 失败后先恢复基线，再尝试下一项；禁止无依据地强制刷写。

## 验收门槛

- 软件或硬复位：至少 `5/5` 成功。
- 彻底断电 10 秒后冷启动：至少 `3/3` 成功。
- 连续运行：无看门狗复位、无串口掉线、无数据流中断。
- 真实数据正确：帧、采样值、读写校验或传输结果符合预期。

示例：

| 外设 | 最终成功标准 |
|---|---|
| 摄像头 | 连续抓帧，格式、分辨率和帧率正确 |
| 传感器 | 连续采样，数据合理且随输入变化 |
| 显示屏 | 连续刷新测试图，无卡死和花屏 |
| 存储 | 擦除、写入、读回和校验一致 |
| 网络 | 可持续传输，断线后能够恢复 |

## 必须保留的文件

```text
完整 Flash 备份
恢复固件
最小诊断源码
最小驱动源码
可直接刷写的稳定固件
关键日志
固件和日志 SHA-256
最终结论文档
```

## 给 AI 的固定指令

```text
先备份完整 Flash。
先建立恢复点。
每次刷写前记录 SHA-256。
禁止使用 --force。
每轮只修改一个变量。
先跑最小诊断，再跑单外设真实数据流。
识别到设备 ID 不算成功。
保存每轮日志。
失败后恢复到已知可用固件。
需要物理断电时再通知我操作。
```

## 核心原则

先可恢复，再调试；先隔离外设，再做集成；先验证真实数据流，再宣布成功。
