# Plant Pet AI 状态融合框架 v0.1

本文件用于冻结当前基础框架，作为后续叶片 AI 训练和开发板移植的参考。

## 结论

当前状态判断不使用 AI 模型。传感器输入具有明确物理意义，适合使用规则引擎、缓冲和趋势判断。

AI 模型训练重点放在叶片图像判断上。模型输出 `leaf_status` 和 `leaf_scope`，再交给规则引擎融合。

视觉模型职责分为两层，主输出是整株级状态，不是单片叶子的情绪判决：

1. 先判断是否存在整株级或大规模叶片异常。如果 `leaf_scope` 为 `widespread`，它可以像原本的病叶逻辑一样强烈影响心情，并给出明确警告。
2. 如果没有大规模异常，整株视觉状态输出健康。个别黄叶、虫咬、病斑、旧伤或局部萎蔫只作为护理提示，不降低当下心情，也不降低 `health_score`。

当前心情主要由土壤湿度、温度、空气湿度和光照计算出的 `comfort_score` 决定；`health_score` 保留为综合展示指标。

## 当前运行载体

```text
Python 本地服务 + 浏览器黑匣子界面
```

当前主要文件：

- `src/plant_pet_ai/state_engine.py`：规则核心。
- `tools/plant_pet_app.py`：黑匣子交互界面和 `/api/analyze` 接口。
- `tools/train_leaf_classifier.py`：叶片分类训练脚本。

## 输入

```json
{
  "soil_moisture": 45,
  "temperature": 26,
  "air_humidity": 55,
  "light": 500,
  "leaf_status": "healthy",
  "leaf_scope": "local"
}
```

触摸是交互事件，不是常驻状态：

```json
{
  "touched": true
}
```

## 输出

```json
{
  "comfort_score": 100,
  "health_score": 100,
  "mood": "happy",
  "face": "😄",
  "issues": [],
  "care_notes": [],
  "advice": ["现在整体很舒服，维持稳定浇水、光照和通风即可。"]
}
```

## 已固定功能

- 固定规则参数。
- 舒适分计算。
- 综合健康分计算。
- 基于舒适分的分段心情逻辑。
- 叶片长期护理提醒。
- 大规模叶片异常警报。
- 触摸互动逻辑。
- 触摸后回到稳定基础表情。
- 测试版表情缓冲。
- 最近状态历史。
- 黑匣子可视化交互界面。

## 后续移植策略

推荐分两步：

1. ESP32 先采集传感器数据，发送给 Python 后端，验证真实数据。
2. 规则稳定后，把 `state_engine.py` 移植为 ESP32 C/C++ 规则引擎。

最终开发板上需要移植的是：

- 固定参数。
- 状态判断。
- 健康分。
- 舒适分。
- 心情和表情映射。
- 叶片护理提醒。
- 表情缓冲。
- 触摸事件逻辑。
- 简化历史记录。

网页界面本身只是当前阶段的调试和演示载体，不是最终必须移植到开发板上的部分。
